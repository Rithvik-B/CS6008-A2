# Phase 7 — Encrypting the Last Mile (DoT)

Reuses Phase 6. The resolver speaks **DoT (TCP 853)** with a **private-CA** certificate for
`resolver.cs6008.local`; clients reach it **by name** and validate the certificate. We then mount
three attacks against two client types and record all six outcomes.

## What's new

- **Private CA + resolver cert** (`pki/make-ca.sh`): the resolver cert's only SAN is
  `DNS:resolver.cs6008.local` (**no IP SAN**); a separate **rogue CA + cert** (same name) is minted
  for the impersonation attack. Clients trust only the real CA (`/ca/ca.crt`).
- **DoT on the resolver**: `tls local-tls {...}` + `listen-on port 853 tls local-tls { any; }`.
- **By name**: clients have `extra_hosts: resolver.cs6008.local -> 172.16.2.10` and connect with
  `dig +tls +tls-ca=/ca/ca.crt +tls-hostname=resolver.cs6008.local @resolver.cs6008.local`.
- **Two clients** (`clients/`): `strict.sh` (DoT only, validate, **no** fallback) and
  `permissive.sh` (DoT, else **cleartext fallback**).

## Deploy & verify (7.2)

```bash
docker build -t cs6008-dnslab:base ../common
docker run --rm -v "$PWD":/phase7 -w /phase7 cs6008-dnslab:base sign/sign-all.sh
docker run --rm -v "$PWD":/phase7 -w /phase7 cs6008-dnslab:base pki/make-ca.sh
docker compose up -d
docker exec client sh /clients/strict.sh            # -> 172.16.1.20 (cert validates cleanly)
# capture on edge-router shows TLS/853 only, zero cleartext DNS (udp/53)
```

## Attacks (7.3) — three attempts × {strict, permissive}

```bash
docker exec attacker make -C /attack

# (i) ALTER in transit: run the on-path DNS forger; DoT intact
docker exec -d attacker sh -c "exec /attack/interceptor eth0 172.16.1.10 172.16.1.30 forge > /tmp/f.log 2>&1"
#   strict -> 172.16.1.20   permissive -> 172.16.1.20   (encrypted answer cannot be altered)

# (ii) ROGUE CERT: attacker runs a rogue DoT server (EVIL CA) as the resolver
docker exec attacker sh -c "ip addr add 172.16.2.10/32 dev eth0; named -c /rogue/named.conf -g &"
docker exec edge-router ip route replace 172.16.2.10/32 via 172.16.1.100
#   strict -> cert REJECTED (fails closed)   permissive -> cleartext fallback -> 172.16.1.30

# (iii) BLOCK 853: deny the encrypted transport, forge the cleartext fallback
docker exec edge-router sh /diversion/divert-on.sh
docker exec edge-router sh /diversion/block-853.sh
#   strict -> timeout (fails closed)   permissive -> cleartext fallback -> 172.16.1.30
```

See `evidence/p7_outcomes.txt` for the full 6-cell matrix.

## Files

- `pki/make-ca.sh` — private CA, resolver cert (DNS SAN only), and the rogue CA/cert.
- `config/resolver/named.conf` — adds the `tls` statement and the `853 tls` listener.
- `clients/strict.sh`, `clients/permissive.sh` — the two client behaviours.
- `rogue/` — the attacker's rogue DoT resolver (config + zone; certs regenerated by make-ca.sh).
- `diversion/` — `block-853.sh`/`unblock-853.sh` (deny transport) and `divert-on.sh` (cleartext forge path).
- `attack/interceptor.c` — unchanged libpcap forger (used on the cleartext fallback).
- `evidence/` — verify (no cleartext), and the six attack outcomes.
